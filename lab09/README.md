# Лабораторная работа №9: Система массового обслуживания с отказами (без очереди)

### 1. Теоретическая база (README.md)
Система может находиться в одном из двух состояний:
* **$S_0$** — канал свободен (система простаивает).
* **$S_1$** — канал занят (система обслуживает заявку).

В файле приведены формулы Эрланга для одноканальной СМО с отказами:
* Вероятность того, что система свободна: $P_0 = \frac{\mu}{\lambda + \mu}$
* Вероятность того, что система занята (она же вероятность отказа): $P_1 = \frac{\lambda}{\lambda + \mu}$

Где $\lambda$ (лямбда) — интенсивность поступления заявок, а $\mu$ (мю) — интенсивность обслуживания.

### 2. Пользовательский интерфейс (`index.html` и `style.css`)
Интерфейс представляет собой простую веб-страницу, куда пользователь вводит три параметра:
* **$\lambda$** — сколько заявок в среднем приходит за единицу времени.
* **$\mu$** — сколько заявок в среднем канал может обслужить за единицу времени.
* **$T$** — длительность симуляции.

После запуска симуляции выводятся **эмпирические** (полученные опытным путем) вероятности простоя, занятости и процента отказов. Смысл лабораторной в том, чтобы сравнить эти практические результаты с теоретическими $P_0$ и $P_1$.

### 3. Алгоритм симуляции (`main.js`)
Это самая главная часть, где происходит имитация процесса методом дискретно-событийного моделирования.
* **Генерация случайных величин:** Функция `expRandom(rate)` генерирует интервалы времени между событиями по экспоненциальному закону распределения (стандарт для простейших марковских потоков).
* **События:** В цикле `while (time <= T)` программа всегда "перепрыгивает" к ближайшему по времени событию. Событий бывает два:
  1. `nextArrival` — пришла новая заявка.
  2. `nextDeparture` — закончилось обслуживание текущей заявки.
* **Логика состояний:**
  * Если **приходит заявка** и система в состоянии `0` (свободна), она переходит в состояние `1`. Генерируется время окончания обслуживания (`nextDeparture`).
  * Если **приходит заявка**, а система в состоянии `1` (занята), счетчик `rejected` (отказы) увеличивается на единицу, статус не меняется.
  * Если **обслуживание заканчивается**, система возвращается в состояние `0`, ожидая новых заявок.

### Специальное задание
В 10% случаев интенсивность обработки заявки удваивается

* **Подведение итогов:** После завершения виртуального времени $T$, скрипт делит время, проведенное в состоянии 0 и 1, на общее время $T$, получая долю времени простоя и работы. Доля отказов вычисляется как отношение отклоненных заявок к общему числу пришедших. Результаты выводятся на экран.
